Performance

The benchmark is a local script, benchmark/benchmark.jl; nothing is run on the docs build and nothing is written to disk. Sizes are given on the command line in increasing order, warm-up runs are excluded from the timings, live memory comes from the GC counter, and a size whose estimated peak memory exceeds 60% of the free RAM is skipped.

Running the benchmark

# one or more population sizes; --parallel N for the threaded mode
julia --project=. benchmark/benchmark.jl 1000 10000 100000 [--parallel N]

# the full local set (Julia from PATH; THREADS env var for the parallel mode, default half the
# CPU threads): serial sizes 10³ … 10⁷, then --parallel 100000
bash benchmark/run_benchmarks.sh

The log of a full run is kept in .development/benchmark/ (not tracked).

Modes

  1. Neutral growth to N (10³ … 10⁷), tree mode versus cell mode.
  2. Growth with resistance (ν = 0.002) and μ = 1, tree versus cell mode.
  3. MTD from 10⁶ cells with α ∈ {0, 0.8}; reports the thinning acceptance fraction.
  4. Cyclic adaptive therapy (the two blocks of AdaptiveOnOff, N_low = N/2, N_up = N, in a FunctionSchedule that stops after exactly six on/off cycles), on a tumour of 10⁵ cells.
  5. Stabilising therapy (the dose is recomputed after every event), 10⁵ cells; reported per event.
  6. Statistics on one 10⁶ population: SFS, burdens, mutation frequencies, Hill numbers and a sample of 1000.
  7. --parallel N: 4 × nthreads runs serially, then on threads; runs per second.

Results

What was measured here, and what was not. Machine: Apple M4 Pro (14 cores, 10 CPU threads reported by Julia), 48 GB RAM, macOS; Julia 1.12.1; ClonalEvolutionTx 0.1.0-DEV; 2026-10-19; Julia started with -t 4. Measured for this page, one invocation each: julia --project=. -t 4 benchmark/benchmark.jl 1000 10000 100000 1000000 (serial modes up to 10⁶, treatment and statistics) and julia --project=. -t 4 benchmark/benchmark.jl --parallel 10000. Not measured here: the 10⁷ rows and the full --parallel 100000 run of bash benchmark/run_benchmarks.sh; they are left to the author and marked "not run" below. Every value is a single seeded run (seeds from derive_seed), warm-up excluded, with no repeats; timings at 10⁶ vary by roughly 10-40% between invocations (the tree-mode 10⁶ rows of three invocations ranged 0.36-0.50 s), so read the figures as orders of magnitude. Time per cell is the wall time divided by the final N; more cells are created than survive (with b = 1, d = 0.5, about 3 thinning ticks are spent per final cell), so the cost per created cell is lower than the figure shown. The script skips any run whose estimated peak memory (1.5 × bytes per cell × N) exceeds 60% of the free RAM; nothing was skipped here.

Treatment

Linear response d_S = 4, Resistance(ν = 0.002, α). The tumour is grown first in cell mode (untimed); the time is the treatment phase only. Ticks and accepted events are summed over the treatment blocks. The cyclic scenario is a FunctionSchedule built from the two blocks of AdaptiveOnOff (N_low = N/2, N_up = N) that stops after exactly 6 complete on/off cycles (12 blocks).

Stabilising therapy costs about 29 ns per tick (30 ns per accepted event), so recomputing the dose after every event does not slow the loop noticeably. With α = 0 the resistant cells are immune and the bound (max αₖ)·D(m) stays at the full drug term while sensitive cells die out, which is why only 56% of the ticks are accepted there; with α = 0.8 the bound is tight.

The comparison with NonMarkovEvolution is indicative only: the models differ (that benchmark uses Exponential division times with fitness-dependent rates and ν = 0.5 driver mutations per daughter, this one a constant-rate birth-death process), and the machines differ (its figures come from a cluster node). Comparison with BirthDeathMutation_AT.jl

benchmark/compare_bdm_at/ (its own environment, with BirthDeathMutationAT.jl added by path) runs the `manuscriptv1` model in both packages and compares the speed and the distributions of a fixed set of statistics. BirthDeathMutation_AT is the predecessor and the reference implementation of v1. The comparison is run once per release and is not part of the test suite.

julia --project=benchmark/compare_bdm_at benchmark/compare_bdm_at/compare.jl        # 200 runs
# growth-phase diagnostic (see the end of the results below): 20 000 runs, about 5 minutes
julia --project=benchmark/compare_bdm_at benchmark/compare_bdm_at/diagnose_growth.jl

The first instantiation of this environment downloads and precompiles the predecessor's dependencies (CairoMakie, DataFrames, GLM, …), which takes a few minutes. The full run took 626 s.

Model and mapping. b = 1, d₀ = 0.5, competition l = 0.5/10⁵ (death_density = N -> l*N ↔ competition = l), LinearResponse(4.0) ↔ LinearSensitivity(4.0), Resistance(ν = 0.002, α) ↔ SelectionFixedAlpha(α, 0.002, typemax(Int)), μ = 1 neutral mutations per daughter in both (the predecessor also draws Poisson(μ) per daughter, so no conversion is needed), detection at N = 10⁴. Thresholds: N_prog = 2·10⁴; adaptive N_low = 5000, N_up = 10⁴, t_max = 100, measured from detection in both packages (the SPEC §9 illustration scaled to N_detect = 10⁴; the manuscript does not fix them). The header of compare.jl lists every mapping, with the lines of the predecessor's code it was checked against. ClonalEvolutionTx runs in tree mode, which keeps the genealogy as the predecessor does.

Configurations. (A) MTD and (B) cyclic adaptive therapy (MTD ↔ SimpleTreatment, AdaptiveOnOff ↔ AdaptiveTreatment) with α = 0.8 are the planned comparisons. With α = 0.8 a resistant cell still has net growth 1 − 0.5 − 3.2 < 0 under full dose. So (A) cures every tumour (200 of 200 extinct in both packages), and (B) cannot progress (200 of 200 reach t_max in both). Time to progression is therefore undefined in both. (A) is compared on time to extinction and on the state at fixed times after detection; (B) on the number of on phases and on the state at fixed times and at t_max. (C) MTD with α = 0 is an extra configuration, not part of the plan: resistant cells are immune, so the tumour progresses (200 of 200 in both). It exercises time to progression and the state at progression.

Method. There are 200 runs per package and configuration, each with its own seed: Xoshiro(derive_seed(base, configuration, run)), with different bases for the two packages, so the samples are independent. The predecessor is called through runsimulation(…; returnextinct = true); a run that dies out before detection is discarded and rerun on the continuing random stream, as restart_on_extinction does. Fixed-time states come from AtTime snapshots in both packages; a run that died out before that time counts as N = 0 with no resistant clones. "Resistant" means α < 1, "burden" is the mean number of neutral mutations per living cell, and "segregating" is the number of distinct neutral mutations in the living cells (the sum of the SFS).

The pass criterion is from the plan: the means differ by at most 5% (relative to the predecessor's mean) and the two-sample KS test (ApproximateTwoSampleKSTest) gives p > 0.01. SE is the standard error of the difference of the means, relative to the predecessor's mean. KS is conservative for integer-valued statistics (ties). Machine: Apple M4 Pro, macOS, Julia 1.12.1, one thread; ClonalEvolutionTx 0.1.0-DEV, BirthDeathMutation_AT 0.2.1; 2026-10-19.

Result: 28 of 29 statistics pass, and the outcome frequencies are identical. The failure is the mean number of resistant cells at detection: +7.87%, while KS gives p = 0.39. This is sampling noise, not a difference between the models. The statistic has a Luria–Delbrück distribution with a heavy right tail: rare runs with an early resistance mutation reach thousands of resistant cells. Its standard error at 200 runs is 17% of the mean, three times the tolerance, so the 5% criterion cannot be resolved for it at this run count. A separate diagnostic of the growth phase, benchmark/compare_bdm_at/diagnose_growth.jl (not part of compare.jl, whose run count is unchanged; its header lists what it computes), checked this with more runs:

  • 20 000 runs per package, new seeds: the means are 667.1 ± 7.2 (ClonalEvolutionTx) and 677.0 ± 7.3 (BDM_AT), a difference of −1.46% (z = −0.97) with KS p = 0.46. The direction of the difference reversed. The tails agree: runs with R ≥ 2000, ≥ 5000 and ≥ 9000 number 900 / 267 / 93 and 907 / 266 / 105.
  • Expectation given the genealogy: at m = 0 resistance is neutral, so the genealogy does not depend on the resistance marks. A cell whose lineage has G divisions is then resistant with probability 1 − (1 − ν)^G, which makes E[R | genealogy] = Σᵢ (1 − (1 − ν)^{Gᵢ}). This quantity is free of the Luria–Delbrück noise. It gives 672.5 ± 0.4 and 673.0 ± 0.4, which agree to 0.07%, and both raw means match it within one standard error.
  • Neutral burden: the mean neutral burden at detection (34.79 and 34.82) equals μ times the mean number of lineage divisions (34.82 and 34.84), as v1's Poisson(μ) per daughter requires.
  • Restarts: the mean number of restarts before detection (0.989 and 0.994) matches the birth–death value of 1.00004 (the script prints it with five decimals).

Speed. Wall time per run is the growth from one cell (restarts included) plus treatment, from a second pass over the same seeds without measurements. After one warm-up run, it is the total divided by 200.

At these sizes (N ≤ 2·10⁴) the predecessor's O(N) deleteat! per death is still cheap, so the speed-up is modest. It is largest in (C). There, after the sensitive cells die out, the predecessor's bound still includes the extinct wild type's drug death (1 + 0.5 + 4 + lN against the true 1 + 0.5 + lN), so, from the rates, at most about 27% of its ticks can be accepted. ClonalEvolutionTx's bound over the living clones is exact there and accepts every tick (these acceptance rates were not measured).

Known semantic differences

None of these differences changes the distribution of the statistics above. They matter when porting analyses.

  • Stabilising t_max origin: BirthDeathMutationAT's MaintenanceTreatment measures `tmaxfrom the start of the maintenance phase;Stabilising` measures it from the schedule start, like every other schedule. This is not exercised here.
  • Extinct clones in the bound: the predecessor's thinning bound is a maximum over every subclone ever created, including extinct ones. This wastes ticks (see Speed) but does not bias the results.
  • Clock at a t_max end: both packages discard the event that would cross t_max, so neither overshoots. The predecessor leaves the clock at the last tick before t_max; ClonalEvolutionTx sets it to exactly t_max. The state is the same; the reported end time differs by less than one inter-tick interval (of order 10⁻⁵ in (B)).
  • Restarts: by default, the predecessor's runsimulation reruns every run whose final population is empty, including a cure under MTD. Unless returnextinct = true, its treatment outcomes are therefore conditioned on non-extinction. restart_on_extinction restarts only the block it is set on (here the growth block).
  • Min rule: SelectionFixedAlpha and SelectionPredefined use the drawn α as it is; only SelectionDistribution applies min(α, α_parent). Resistance always applies the min rule. The two are identical for a fixed α, as here.
  • Measurement timing: the predecessor's AtTime(T) holds the state at T, but it is stamped with the time of the first tick after T; ClonalEvolutionTx's is stamped exactly T. The predecessor's trajectory grid starts at absolute time 0, not at detection, and its AtTreatmentToggle fires at the start of every on and off phase. ClonalEvolutionTx's AtBlockEnd fires at the end of every block.
